# Odyshell 0.15.0

Odyshell 0.15.0 adds manually approved Host Shell Sessions so an agent can choose commands as it
works instead of predicting the entire shell interaction before approval.

- Every Host Shell request requires manual approval and is bound to one host machine and Session
  lifetime; it cannot be autoapproved or delegated.
- Approved commands run as the existing Client user, start in that user's Home by default, and may
  use any path that account can access.
- Each command runs in a fresh native login shell with bounded input, output, timeout and an
  allowlisted base environment. Host Shell does not provide a PTY or an additional sandbox.
- Protocol v3 rejects protocol v2 Client Profiles. Remove and reenroll existing Profiles after
  updating the Server and CLI.

Install the release:

| Package manager | Command |
| --- | --- |
| pnpm | `pnpm add --global @odyshell/cli@0.15.0` |
| npm | `npm install --global @odyshell/cli@0.15.0` |
| Yarn | `yarn global add @odyshell/cli@0.15.0` |
| Bun | `bun add --global @odyshell/cli@0.15.0` |

This minor release must be installed globally with one of the package-manager commands above; the
Client's patch-only updater cannot cross from `0.14` to `0.15`.

After installing the new CLI, recreate each protocol v2 Profile instead of copying or editing its
old configuration:

```bash
ods down --profile default
ods profiles remove default
# Delete the stale machine in the dashboard, then run its newly generated ods up command.
```

Repeat those steps for every named Profile.
