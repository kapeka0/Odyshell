# Odyshell 0.9.0

Odyshell 0.9.0 replaces permanent machine grants with persistent Agent identities and temporary
Sessions.

## Compatibility

Use Server, Client, CLI, SDK, and protocol `0.9.x` together. The MCP server ships inside
`@odyshell/cli`.

## Changes

- Agents register once and hold no machine authority.
- Every task requests an immutable Session with per-machine capabilities and typed restrictions.
- The API and TypeScript SDK expose Session request, one-time claim, cancellation, renewal, and
  Timeline operations.
- The web app approves or denies requests and provides Session cancellation, Timeline inspection,
  and export. The CLI lists Sessions and runs scoped Operations.
- The local MCP requests, claims, and uses scoped Sessions without returning their credentials to
  the model.
- Independent Agents can use versioned Autoapproval and Delegation Policies.
- Signed Event Sinks deliver privacy-minimal, operational, or diagnostic Timeline events to
  customer-owned HTTPS endpoints. Structured secret fields are removed; diagnostic output is an
  explicit verbatim export.
- One host can run several isolated Client Profiles.
- Clients report software, protocol, platform, runner, and supported-capability metadata.
- `ods client update` verifies compatible npm artifacts, restarts the platform service, and rolls
  back on activation failure.
- Live dashboard credentials require canonical signatures, and Windows services use native path
  semantics on every supported host.
- Legacy Agent Access and direct Session routes return migration guidance and no longer authorize
  Operations.

## Migration

Take a PostgreSQL snapshot before deploying the 0.9 Server. Startup performs the authority
cutover, preserves Workspaces, machines, Client Profiles and retained history, revokes legacy
credentials, and closes legacy authority. Startup fails closed if the cutover is incomplete.

Reconnect integrations with:

```bash
ods agent login "My Agent"
```

Then request a Session for each task. See the [migration guide](https://odyshell.com/docs/migration)
for self-hosted rollback rules.
