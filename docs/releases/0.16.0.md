# Odyshell 0.16.0

Odyshell 0.16.0 hardens the smallest production workflow before broader market iteration. It is a
minor pre-1.0 release because programmatic Host Shell requests now require a stable Task Run
identifier and structured filesystem Operations have explicit resource ceilings. The Client wire
protocol advances to v4 because recursive `fs.remove` is no longer a valid Operation.

- Host Shell request and claim calls must use the same opaque `runId`. Authority can be reused for
  corrective commands in one task, but unrelated tasks cannot inherit the Session.
- Structured filesystem reads are limited to regular files of 1 MiB, and writes reject decoded
  content above 1 MiB. Listings fail above 1,000 entries; searches fail above 2,048 visited nodes
  or 32 directory levels. `fs.remove` now deletes one file or empty directory and rejects recursive
  removal. Cancellation and Session closure are observed cooperatively and suppress late results.
  Relative scopes reject symlinks that resolve outside their approved subtree.
- Cloud Agent creation enforces the plan's active-Agent limit atomically for both independent and
  Managed Agents, including concurrent approvals.
- In-memory rate-limit state prunes expired clients and rejects new keys at a fixed capacity rather
  than growing without bound.
- Patched production dependencies remove known audit findings, and CI plus the release workflow
  now reject high-severity production dependency advisories.
- Machine enrollment remains a delegated, single-use flow: an authenticated member generates the
  command, while the target machine runs `ods up --token ...` without `ods login`.

Install the release:

| Package manager | Command |
| --- | --- |
| pnpm | `pnpm add --global @odyshell/cli@0.16.0` |
| npm | `npm install --global @odyshell/cli@0.16.0` |
| Yarn | `yarn global add @odyshell/cli@0.16.0` |
| Bun | `bun add --global @odyshell/cli@0.16.0` |

Protocol v4 is intentionally incompatible with protocol v3. The CLI's patch-only Client updater
cannot cross from `0.15` to `0.16`, so install the new CLI with one of the commands above and update
the Server before restarting each enrolled Profile with `ods down --profile <name>` and
`ods up --profile <name>`. Existing Profile configuration remains valid; re-enrollment is not
required.
