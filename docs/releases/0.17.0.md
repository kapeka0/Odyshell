# Odyshell 0.17.0

Odyshell 0.17 makes account and Machine onboarding independent from Agent setup while preserving
default-deny authority.

## Added

- Every successful Cloud account signup creates and activates an Organization named after the
  user. The first self-hosted account bootstraps the deployment's single sovereign Organization.
- Machines can be registered and remain connected before any Agent exists.
- `ods up --agent-id` is optional. Omitting it persists an empty Agent allow-list that denies every
  Task locally.

## Changed

- Signup now enters the dashboard directly instead of requiring a separate Organization form.
- The Machine enrollment screen treats the initial Agent as optional and clearly describes the
  default-deny result.

## Security

- Default Organization provisioning is serialized per account, uses the official Organization
  API, and binds the new Human session to the resulting membership.
- Agent-free Machine enrollment does not imply wildcard authority. The Client continues to reject
  every Agent not explicitly present in Local Policy.

## Upgrade

Install the coordinated Linux CLI:

```bash
npm install --global @odyshell/cli@0.17.0
```
