---
title: MCP
description: Let an MCP-compatible agent request temporary access to a private machine.
---

`ods mcp` runs a local MCP server using the workspace authorized by `ods login`. The agent has a
persistent identity but no machine authority until a member approves a temporary Session.

## Install

```npm
npm install --global @odyshell/cli
```

## Configure an agent

First sign in:

```bash
ods login
```

Then add:

```json
{
  "mcpServers": {
    "odyshell": {
      "command": "ods",
      "args": ["mcp"]
    }
  }
}
```

The MCP process uses the existing local `ods` configuration. Its identity is saved locally. A
claimed Session Credential stays in MCP memory and is never returned in a tool result.

## Request an operation

The approval-based workflow exposes four tools:

1. `machines_list` finds the target machine.
2. `session_request` accepts one typed operation and returns an approval URL.
3. `session_status` checks the decision and privately claims the credential once.
4. `operation_execute` executes only that operation with the claimed Session.

The operation determines the capability and restriction automatically. Filesystem operations use
an exact path, `process.exec` uses an exact executable and arguments, and `docker.logs` uses an
exact container. Approval codes expire, are single-use and are bound to their Workspace.

The Server validates Session identity, machine, capability, path and expiry on every Operation.
The Client applies its local policy independently.

`process.shell` is not available through restricted Sessions. Agents should request
`process.exec` with an explicit executable and argument array.
