---
title: Agents
description: Give a persistent agent temporary, least-privilege machine access.
---

An Agent is a persistent programmatic identity. Signing in with `ods login` lets `ods mcp`
register that identity without granting it access to a machine.

For an interactive task, the Agent requests a temporary Session with a purpose, duration, and one
or more independent machine scopes. A workspace member reviews every machine, capability, and
restriction in the browser. The Agent then claims a Session Credential once; the Server stores
only its hash.

## Connect an agent

Install the CLI in the agent's environment:

```npm
npm install --global @odyshell/cli
```

Sign in and configure the MCP:

```bash
ods login
ods mcp
```

For an unattended runtime, register an Independent Agent instead:

```bash
ods agent login "OpenClaw"
```

Open the displayed URL as a workspace administrator. Approval creates the persistent Agent and
returns a 90-day Agent Credential to the runtime. It can request Sessions and inspect its own
requests, but cannot execute an Operation or administer the workspace. Rotate it before expiry;
the previous credential remains valid for at most ten minutes.

The current MCP shortcut requests one exact file read. The Session protocol also supports
multi-machine scopes with explicit filesystem paths, exact `process.exec` program and argument
rules, and Docker container names.

Its effective authority is the intersection of:

1. the selected machine scope and its typed restrictions;
2. Session status and expiry;
3. the target machine's local policy;
4. the operating-system permissions of the Client process.

## Expiry

Session authority begins when it is claimed and cannot outlive its expiry. A Session Credential
cannot create another Session or change its approved scope. The Server revokes the credential and
the Client cancels active work when the Session expires or is cancelled.

Renewal never extends an active Session. It creates a successor with the same immutable scope, a
new expiry, and a new approval. Cancelling a Session is safe to retry and immediately prevents
credential reuse.

Verified request, approval, target, Operation result and close events form the Session Timeline.
Privacy-minimal Timeline events do not contain file contents or credentials.

Open **Sessions** to search current and historical Sessions, inspect their machine scopes and
review the verified Timeline. Active Sessions also appear between their Agent and machines on the
Overview canvas. An Agent remains visible when it has no active Session.

## Autoapproval policies

An Independent Agent can propose a temporary approval ceiling with exact machines, capabilities,
typed restrictions, a maximum Session duration, and a policy expiry. The policy remains inactive
until a workspace administrator reviews its standalone approval page.

Requests wholly inside an active policy are approved automatically. A request that adds a machine,
capability, restriction, or longer duration remains pending for a human; Odyshell never partially
approves it. Pausing or revoking a policy stops future automatic approvals without changing
Sessions already issued from an earlier version.

Open **Policies** to review current and historical versions. Every autoapproved Session records the
exact policy ID and version that justified it.

## Managed agents

An Independent Agent can propose a Delegation Policy with an exact scope, Session duration,
validity, and Managed Agent limit. After an administrator approves it, the Agent can create
persistent Managed Agent identities inside that ceiling.

A Managed Agent has no durable credential and cannot create another Agent. Its parent requests
Sessions in its name and gives a worker only the claimed Session Credential:

```ts
const child = await ods.createManagedAgent({
  name: "Dependency updater",
  scopes,
  maxSessionSeconds: 600,
  validForSeconds: 60 * 60,
})

const request = await ods.requestAgentSession({
  agentId: child.id,
  agentName: child.name,
  purpose: "Check dependency updates",
  scopes,
  durationSeconds: 600,
  runId: "update-run-42",
})
```

The Timeline identifies the Managed Agent that executes, its requesting parent, and the optional
run identifier. Pausing or replacing the parent Delegation Policy blocks new child Sessions.
Disabling a Managed Agent closes its active Sessions; revoking the parent credential also disables
its children and their active access.

## Pre-scoped access

Agent Access tokens remain available for trusted, unattended integrations. A member chooses their
machines, capabilities and expiry from **Agents**. Revocation immediately blocks new work and
closes active sessions.
