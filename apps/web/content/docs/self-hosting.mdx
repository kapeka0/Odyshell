---
title: Self-hosting
description: Run the sovereign Odyshell control plane and PostgreSQL on your infrastructure.
---

Self-hosting uses the same web app, Better Auth identity layer, Server, PostgreSQL schema, remote
MCP and HTTP protocols, dashboard, and Linux Client as Cloud. Identity, policy, Task, audit, and
credential data stay in the deployment owner's PostgreSQL database.

## Local stack

```bash
pnpm install
cp .env.example .env
cp apps/web/.env.example apps/web/.env.local
docker compose up -d --build
curl --fail http://127.0.0.1:4100/health
```

Set a random `BETTER_AUTH_SECRET` of at least 32 characters and the same random
`ODYSHELL_WEB_KEY` in both environment files. Keep `BETTER_AUTH_URL=http://localhost:3000`, open
that address, create the first local account, and bootstrap the single Organization.

The bundled example values are for local development only. Do not expose them to the Internet.

## Production boundary

- Run PostgreSQL with TLS and backups you have restored in a drill.
- Put web, OAuth/MCP, HTTP, and Client gateway traffic behind TLS.
- Keep `BETTER_AUTH_SECRET`, `ODYSHELL_WEB_KEY`, database credentials, and optional OIDC secrets in
  a secret manager.
- Set `BETTER_AUTH_URL` and every public Server/web URL to their canonical HTTPS origins.
- Keep development credentials disabled in production.
- Run one Server replica in the current release because live Client connections are held in memory.
- Run every Client as a dedicated Linux user with least privilege.

Self-hosted mode is single-Organization. Missing sovereign Organization identity fails enrollment
before the one-time token is consumed.

## Connect the system

1. Add the Server's `/mcp` resource to the external Agent runtime.
2. Complete OAuth and approve the Organization-bound Agent installation.
3. Install `ods` on the target Linux host.
4. In **Machines**, select **Add Machine**, choose the Agent, and run the generated command.
5. From the Agent, request a Task and execute Commands through MCP or canonical HTTP.

```npm
npm install --global @odyshell/cli

ods --server https://api.ods.example.com up \
  --token <single-use-token> \
  --name production-api \
  --agent-id <agent-id>
```

The Machine initiates the connection and needs no inbound port, SSH credential, or VPN route.

For the complete deployment variables and operations checklist, see the
[repository self-hosting guide](https://github.com/kapeka0/odyshell/blob/main/docs/self-hosting.md).
