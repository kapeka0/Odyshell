---
title: Sessions
description: Grant an Agent temporary, scoped access to one or more machines.
---

A Session is the only object that grants an Agent machine authority. Agent identities remain
persistent, while every Session has an immutable scope and a maximum duration of 24 hours.
Its duration starts when the first target becomes ready. Opening is bounded
to one minute and does not consume the granted duration.

## Create a Session

An Agent normally calls `session_request`. Odyshell returns a browser link when a member must
approve the request. The Agent checks `session_status` after the decision and uses the explicit
`sessionId` for every Operation.

Before creating a request, the Agent checks `sessions_list`. If the same MCP installation already
has a ready, unexpired Session covering every requested machine and Operation, Odyshell returns
that Session directly instead of asking for duplicate approval. The Server repeats this check even
if the model skips it.

Every request has a short title used in tables, notifications and the canvas. A longer purpose is
optional. MCP callers may omit the title; Odyshell uses the purpose or derives a short title from
the requested authority before creating the request.

Workspace members can also select **New** on the Sessions page. Choose an Agent with an active
credential, an online machine, a duration, and explicit capabilities:

- **Read only** grants structured filesystem inspection and reading.
- **Host Shell** separately grants successive native shell commands under `host.shell`. Selecting
  it adds no structured capabilities; members can select those independently when the task needs
  both kinds of authority.

Every selection is intersected with the machine's Client policy. Host Shell runs as the Client's
operating-system user, starts each command in that user's Home by default, has no sandbox or
isolation, can reach that user's files, credentials, network, and services, and may persist changes
after the Session ends. If the installed Linux service has sudo enabled, or a foreground Client
detects effective `sudo -n`, the form adds a separate root-access warning. Manual filesystem
capabilities still run without automatic elevation.
Exact `process.exec` and Docker requests remain available through Agent, MCP, and API flows instead of
exposing low-level program arguments or container restrictions in this form. A manual Session is
approved by its creator and opens immediately when that Agent has an active MCP installation.
Otherwise, the Agent claims the approved request when it next connects.

The dashboard offers 5 minutes, 15 minutes, 1 hour, 4 hours, 8 hours, or 24 hours and defaults to
1 hour. API, SDK, and MCP requests can instead supply any whole-second duration from 60 seconds to
24 hours; MCP defaults to 1 hour when omitted. Sessions cannot be widened, extended, or made
permanent. Create a new Session when authority must change.
If the Client does not acknowledge a target within 60 seconds, Odyshell fails that target closed.
Other ready targets remain usable. A disconnected target can retry the same approved authority if
its Client reconnects before the Session expires.

Transport loss alone does not terminate an already authorized Operation. The disconnected Client
accepts no new Operations, continues enforcing the local Operation timeout and Session expiry, and
keeps only bounded output. It reconciles the result after reauthentication; the Server does not
assume that a disconnected command succeeded or failed. Output remains unconfirmed until the
Server acknowledges the terminal result; if the connection or Client disappears first, Odyshell
reports that output as truncated instead of claiming every chunk was stored.

Graceful authority loss cancels the active process group. This is different from an abrupt Client
crash: without a separate Operation supervisor, a detached POSIX command can continue until it
exits or is stopped externally. After restart, Odyshell records its execution result as unknown.

## Timeline

Open a Session to follow its lifecycle and Operations chronologically. The Timeline updates while
the page is open and attributes actions to the Agent, the responsible member, or Odyshell.

The Workspace logging level is captured when the Session is requested and never changes for that
Session:

- **Privacy-minimal** keeps lifecycle, Operation kind, status and exit code. It excludes commands,
  paths, stdout and stderr.
- **Operational** adds commands, paths and available stdout and stderr with automatic secret
  redaction.
- **Diagnostic** keeps complete available details and can contain secrets.

Environment values and standard input are never persisted. Host Shell inherits an allowlisted base
environment rather than all Client variables; explicit values apply only to one Operation. The
POSIX login shell can still load user startup files. Command and output detail remains temporary
and becomes unavailable when Operation retention expires.

Operation output remains temporary and is eligible for deletion after one hour by default. Older
Timeline events keep their structural result without recreating deleted output.
