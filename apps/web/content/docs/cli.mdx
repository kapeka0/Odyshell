`ods` uses Odyshell Cloud by default. Select a self-hosted Server with `--server` or
`ODYSHELL_SERVER_URL`. Add `--json` when an agent needs structured output.

## Install

Requires Node.js 24 or newer:

```npm
npm install --global @odyshell/cli
```

## Common commands

```bash
ods login
ods status
ods machines
ods ping my-machine
ods exec my-machine -- uname -a
ods fs list my-machine .
ods fs read my-machine README.md
ods docker logs my-machine api --tail 100
ods audit
```

## Client lifecycle

- `ods up` verifies Server reachability, enrolls when needed, and starts the background Client on
  Linux, macOS, or Windows.
- `ods down` stops that Client.
- `ods client doctor` checks the installed version, protocol, prerequisites, service, and configuration.
- `ods client update` verifies and installs the latest compatible patch, restarts the service, and
  restores the previous version if activation fails.
- `ods client enroll` creates a machine identity explicitly.
- `ods client start` runs the Client in the foreground.
- `ods profiles ls` lists local Profiles and their service state.
- `ods profiles status <name>` inspects one Profile.
- `ods profiles remove <name>` stops a Profile and deletes its local identity.
- `ods reset --yes` signs out and removes every local Profile, including legacy identities.

Use `--profile <name>` with `ods up`, `ods down`, or `ods client status` when one host connects to
several Workspaces or Servers. Profiles are isolated and can run simultaneously. The default name
is `default`; `--profile` and `--config` cannot be combined.

Profile commands also support `--json` for automation:

```bash
ods --json profiles ls
```

Local removal does not delete Cloud machine records. They remain offline until removed from the
dashboard.

## Sessions

High-level operation commands request a Session derived from the exact operation. If no matching
policy exists, the CLI prints an approval URL and waits. The Session Credential is claimed once,
used for the operation and revoked when the command finishes.

`ods shell` is deprecated because unrestricted shell text cannot be translated into a narrow
Session. Use `ods exec <machine> <program> [args...]`.

## Agent integrations

`ods mcp` starts the local MCP server over stdio. After `ods login`, it creates one persistent
local Agent identity. That Agent requests temporary Sessions; the user approves the machine,
typed operation and duration in the browser.

The MCP exposes machine discovery and ping, Session request/status/completion, typed execution and
the verified timeline. It cannot enroll machines, manage people, expose credentials, or use
administrator commands.
