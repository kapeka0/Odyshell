---
title: Commands
description: Run bounded asynchronous shell work inside an active Session.
---

Each Command is an independent non-interactive shell process inside one active Session. It executes as
the operating-system user bound during Machine enrollment. Odyshell does not sandbox, elevate, or
roll back that user.

## Input

`command_run` and `POST /v1/sessions/:sessionId/commands` accept:

- the complete shell command as text;
- an optional absolute working directory;
- an optional timeout inside the Session and Local Policy limits;
- a UUIDv4 idempotency key for that logical Command.

Caller-provided environment variables, standard input, PTYs, and persistent shell state are not
supported. A later Command starts independently and does not inherit changes to shell state from an
earlier one.

## Asynchronous execution

Creation returns a durable Command ID. Poll `command_get` until terminal and read retained
stdout/stderr chunks with `command_output`, passing the last sequence cursor as `after`. Output is
bounded by Local Policy, can be truncated, and expires according to the Organization retention policy.

`command_cancel` requests process-tree termination. Cancellation is not reported as complete until
the Client confirms a terminal result. After an abrupt Client crash, reconciliation reports an
unknown or failed outcome instead of claiming the detached process stopped.

## Evidence

Durable audit records the exact command, working directory, timeout, Agent, Machine, Session, status,
exit code when known, timestamps, and bounded stdout/stderr. It never stores OAuth credentials in
the timeline.
