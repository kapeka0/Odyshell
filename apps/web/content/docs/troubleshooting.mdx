---
title: Troubleshooting
description: Diagnose common CLI, enrollment, connectivity, and operation failures.
---

## `fetch failed`

The CLI could not reach the configured Server. Check the URL, DNS, TLS certificate, proxy, and
whether the Server health endpoint is reachable from the same machine:

```bash
curl --fail https://server.example.com/health
ods client doctor
```

`ods up` checks this endpoint before reporting that the background Client is running. A local
service can be active while DNS or outbound Internet access is unavailable.

## Machine is offline

The machine record exists but its Client connection is not active:

```bash
ods client status
ods up
```

For a foreground Client, run `ods client start` and keep the process alive. Also verify outbound
HTTPS/WSS access to the Server.

## `client_upgrade_required`

The machine authenticated with an incompatible protocol and remains offline. On that machine:

```bash
ods client update
ods client doctor
```

Only patch updates inside the installed pre-1.0 minor line are automatic. Follow the release
migration guide for a minor version change.

## CLI still shows the previous version

More than one package manager may have installed `ods`. Find which executable appears first:

```bash
# Windows PowerShell
Get-Command ods -All

# Linux or macOS
type -a ods
```

Update `@odyshell/cli` with the package manager that owns the first result, then restart each
Profile with `ods down --profile <name>` followed by `ods up --profile <name>`.

## `client_already_enrolled`

The selected configuration already contains a machine identity. Start it without enrollment
options:

```bash
ods up
```

To enroll a separate identity, choose a new Client Profile:

```bash
ods up --profile company <enrollment-options>
```

Do not overwrite or copy an existing machine identity. If migration reports two default
identities, verify which machine is active and remove the unused configuration before retrying.

## `client_config_server_mismatch`

The selected local identity belongs to another Server. Choose an isolated Profile:

```bash
ods up --profile company <enrollment-options>
```

List local identities with `ods profiles ls`, then remove a known unused Profile with
`ods profiles remove <name>`. Use `ods reset --yes` only when every local Profile and the CLI login
on that host should be deleted.

## `machine_ping_timeout`

The Server knows the machine connection but did not receive the end-to-end pong in time. Check
Client logs, reconnect it, and confirm that Server and Client versions match.

## Operation denied

Compare the capability required by the operation with both the agent credential and the
machine's local `--allow` policy. Also check credential expiry, machine assignment, filesystem
workspace boundaries, and operating-system permissions.

## `sudo` cannot gain privileges

Linux Client services set `NoNewPrivileges` unless the machine owner opts in for that Profile.
First configure a narrow passwordless sudoers rule, then run locally:

```bash
ods profiles configure default --allow-sudo
```

The command fails closed when `sudo -n true` does not succeed. Use `--deny-sudo` to restore the
default. A Profile with sudo enabled makes approved process Sessions root-capable; structured
filesystem operations remain unprivileged.
