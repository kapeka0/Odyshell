---
title: Concepts
description: The small set of identities and boundaries used by Odyshell.
---

## Workspace

The isolation boundary for machines, Agents, Sessions, Operations, and Control Events.
Odyshell Cloud currently exposes one workspace for each organization.

## Machine

A private computer running an Odyshell Client. The Client owns a machine identity, applies a
local capability policy, and initiates the outbound connection to the Server.

## Agent

A persistent identity for a programmatic client. An Independent Agent authenticates with a
rotatable Agent Credential. A Managed Agent is controlled by its parent and never receives a
durable credential.

## Agent Credential

An expiring, revocable credential that identifies an Independent Agent. It can request Sessions,
but it cannot execute Operations or grant itself machine authority. The plaintext credential is
returned once; the Server stores its hash.

## Capability

A named class of Operation. Both the approved Session scope and the target machine policy must
allow the required capability.

## Session

A temporary, immutable authorization for one task. It has independent per-machine scopes and
cannot outlive 24 hours. A member can approve or deny a pending request; either decision is
terminal for that request.

## Autoapproval policy

An administrator-approved ceiling for an Independent Agent. It can automatically approve only
Session requests that are strict subsets of its machines, capabilities, typed restrictions,
maximum duration, and validity. `host.shell` cannot appear in an Autoapproval or Delegation Policy;
Host Shell always requires a human decision.

## Operation

A typed request such as `process.exec`, `fs.read`, or `docker.logs`. Structured operations make
authorization and validation clearer than treating every action as shell text.

## Control Event

A durable, privacy-minimal lifecycle record. It identifies who acted, what kind
of action occurred, the target, time, and result. It does not contain commands,
paths, stdout or stderr.

## Session Timeline

The chronological record for one Session. The workspace logging level captured
by the Session controls its detail: Operational can show automatically redacted
commands, paths, stdout and stderr, while Diagnostic can show raw values that
may include secrets. Privacy-minimal remains structural. Environment values and
standard input are never persisted.
