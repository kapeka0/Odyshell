---
title: Authority migration
description: Move from Agent Access credentials to persistent Agents and temporary Sessions.
---

Current Odyshell Servers migrate authority automatically at startup. Existing Workspaces,
machines, Client Profiles and retained Activity remain available. Agent Access credentials and
their active Sessions are revoked; a disabled Agent identity preserves the old display name and
history.

Reconnect each integration once:

```bash
ods agent login "My Agent"
```

The Agent can then request a Session for each task. For repeated unattended work, approve a
temporary Autoapproval Policy instead of creating a permanent machine grant.

Legacy Agent Access and direct Session-creation routes return `410` with the replacement interface.
They never silently translate a permanent grant into a new Session.

Self-hosted operators should take a PostgreSQL snapshot before upgrading. Rolling back the
application or schema does not reactivate revoked credentials. Restore a pre-cutover database
snapshot only before accepting new Sessions, or continue forward and register new Agent
Credentials.

## Update Server and Client together for protocol v4

Odyshell 0.16 rejects protocol v3 peers because recursive `fs.remove` is no longer accepted. Update
the Server and CLI together, then restart each enrolled Profile. Existing Profile configuration
remains valid and re-enrollment is not required.

## Legacy: re-enroll Client Profiles for protocol v3

Protocol v3 intentionally rejects protocol v2 Client Profile configuration. Stop and remove each
old Profile, remove its stale machine record in the dashboard, then generate a new enrollment
command and run it with the same Profile name:

```bash
ods down --profile default
ods profiles remove default
# Run the new ods up command generated by the dashboard.
```

There is no automatic local configuration conversion. Host Profiles no longer have a
`workspaceRoot`; relative filesystem work and Host Shell commands start in the operating-system
user's Home. Docker Profiles require an explicit `mountSource`, supplied during enrollment with
`--runner docker --mount-source <absolute-path>`. Recreate and re-enroll Profiles instead of
copying or hand-editing protocol v2 configuration.
